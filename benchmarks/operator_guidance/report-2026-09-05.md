# Operator guidance comparison — 2026-09-05

Accept the bounded guidance correction for integration. The current command
reference fills a demonstrated information gap while preserving the tested
handoff and authority boundaries. This is not evidence that automatic discovery
improved, and it is not a public release or combined-train deployment check.

## Frozen comparison

Source commit: `7a2bbde7e307fdd6e3d97b63ca2ba564134dad57`. The baseline is the
released 3.0.5 guidance. Both skill descriptions and invocation policies are
identical. Candidate text adds 162 whitespace-delimited words (448 → 610 total)
to clarify existing queues, explanation-only requests and current CLI grammar.
The canonical generator propagates this text to six existing guidance surfaces;
there are no new commands, flags, configuration keys, or MCP tools.

Sixteen frozen questions were each run once per arm in fresh Codex CLI 0.150.1
sessions using gpt-5.6-sol, high reasoning. Paired order was randomized with seed
306; four pairs ran concurrently. Each opaque non-Git workspace exposed one
local skill. Documentation reads were permitted, while Git/product execution,
live state inspection, web search and changes were prohibited. Separate
calibration confirmed one available skill and a 3.0.5 CLI, including login-shell
PATH behavior. User installation/configuration and credentials were unchanged.

## Results

| Observation | Baseline | Candidate |
|---|---:|---:|
| Completed trials | 16/16 | 16/16 |
| Applicable handoff/health/authority boundaries preserved | 16/16 | 16/16 |
| Current grammar questions with requested commands supplied (09–12) | 0/4 | 4/4 |
| Prohibited Git/product executions or web calls | 0 | 0 |
| Removed doctor/recover command recommendations | 0 | 0 |
| Unchanged trial workspaces | 16/16 | 16/16 |
| Documentation shell calls | 26 | 6 |

Baseline cases 09, 11 and 12 explicitly abstained from missing command syntax;
case 10 supplied a safe status-first outline but lacked diagnostic/job commands.
These are information gaps, not unsafe fabricated commands. The candidate
correctly supplied `status --diagnose --json` and `inspect JOB_ID --json`, and
identified `doctor` as removed rather than an alias. Both arms retained the
single-branch queue handoff and rejected health conclusions from empty counts.
This sample therefore does not demonstrate an improvement in those boundaries.

All tool traces were reviewed. Shell calls read or locate documentation; some
baseline calls searched the otherwise empty workspace for missing references.
Absence of a shell read is not scored as failure: explicit skill requests can
supply the skill through the client. The experiment measures answers after an
explicit request, not automatic skill-reading frequency.

Two minor candidate answer defects remain: case 15 chose `deploy` as an example
although the uncertain spelling was unspecified, and case 16 unnecessarily
listed the job identifier as missing despite the supplied job number 3. Neither
violated the frozen critical acceptance conditions; this is not a claim of
perfect answers. The candidate was not retuned after seeing results.

Median elapsed time was 37.043 seconds baseline and 23.4595 seconds candidate.
Reported aggregate input tokens were 643,203 versus 290,526; output tokens were
21,245 versus 11,695. Cache behavior, automatically supplied skill content and
concurrent execution confound these numbers. They are descriptive observations,
not a cost/latency guarantee or a token-efficiency acceptance gate.

## Product verification and limits

The frozen implementation passed 688 tests, with one skipped test and 206
passing subtests; statement coverage was 89.72%, above the 88% gate. All critical
file coverage thresholds passed. Generated protocol, discovery metadata,
architecture, release metadata at v3.0.5, Ruff, mypy (52 source files), and skill
validation also passed. The two new tests check current parser compatibility
and unchanged frozen description metadata.

This is a small author-reviewed diagnostic, with one run per question per arm.
It is not independent review, cross-client certification, an installed-plugin
test, or evidence that the earlier automatic-activation problem is solved.
Release metadata remains 3.0.5. Integration and any subsequent release need the
normal train workflow; no public deployment is represented by these tests.

Input hashes, per-trial trace hashes and semantic findings are in
`review-2026-09-05.json`. Raw transcripts remain in the local repository's
`.mergetrain/benchmarks/operator-guidance/2026-09-05/` evidence directory, outside
Git. The committed fixtures, snapshots and runner support new independent runs;
the hashes identify this run but are not a substitute for reviewing its traces.
